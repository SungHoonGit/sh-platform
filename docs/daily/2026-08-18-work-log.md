### 5. Nginx Web Log 대시보드 생성 (Loki) ✅

- **학습**: nginx 로그는 JSON이 아니라 **combined 포맷**이라 `| json` 불가, `| pattern` 사용 필요

### 8. DatasourceNoData 알림 함정 해결 ✅
- **증상**: 알림 등록 후 6/8/9/11번 규칙이 반복 발화 → "DatasourceNoData" 메일 수신
- **원인**: 이 규칙들은 평소 No data가 정상인데, 규칙의 **"Alert state if no data"가 기본값(NoData)** 그대로라 No data가 알림으로 발화
- **해결**: 각 규칙의 **Set evaluation behavior → Configure no data and error handling**에서 `Alert state if no data`와 `Alert state if execution error`를 **`Normal`**로 변경
- **학습**: Grafana 11부터 `OK` 명칭이 `Normal`로 변경됨. 로그 기반 규칙(평소 No data가 정상)은 반드시 Normal로 설정해야 함
- **결과**: 규칙 상태 전부 Normal, 메일 발화 중단. SMTP 메일 발송 동작도 동시에 검증됨

## 신규로 알게된 것 (2026-08-18)
- **Loki 보관 주기(retention)** 는 `limits_config.retention_period` + compactor로 설정 (기본 7일, `168h`)
- **로그 기반 알림(8~11)의 No data는 정상** — 해당 로그가 없으면 당연히 데이터 없음, 이상 발생 시에만 발화
- **Grafana 11은 "OK"가 "Normal"** — No data 상태 설정명이 변경됨 (헷갈림 주의)
- **DatasourceNoData 알림 = No data 발화** — 실제 장애가 아니라 "데이터 없음" 알림. No data가 정상인 규칙은 `Alert state if no data = Normal` 필수
- **nginx access 로그는 combined 포맷** → `status` 라벨 없음, `| pattern` 파서로 추출해야 `sum by (status)` 가능
- **journald의 한계**: 크기 제한(SystemMaxUse) 초과 시 오래된 로그 자동 삭제, 서비스별 회전/보관 정책 불가 → **MSA는 파일 로그가 표준**
- **로그 경로 휴대성**: 절대경로 하드코딩 대신 Spring Boot `logging.file.path`(=`LOG_PATH`) 사용 → 기본 상대경로 + 서버 환경변수 오버라이드
- **`reject_old_samples_max_age: 168h` ≠ 보관 기간**: Loki에서 이건 "7일보다 오래된 로그 수신 거부" 기준이지 저장/보관 기간이 아님. 보관은 `retention_period` (미지정 시 무기한 또는 기본값)
- **DB 알림은 Prometheus 데이터소스 필수** — MySQL 데이터소스는 직접 DB 쿼리용, 모니터링은 mysqld_exporter 경유
- **DB 커넥션 알림은 WAS(HikariCP) 기준이 아니라 DB(MariaDB) 입장의 연결 수**
- **Load 평균 기준**: 단일 코어 서버에서 `cores × 4` = 4
- **P95 응답지연**: 히스토그램 활성화 필요, `is above` 값은 초 단위
- **Grafana SMTP**: 서버에서 메일 발송 설정 완료 (Step 1), 발송 테스트는 규칙 발화로 검증 예정
