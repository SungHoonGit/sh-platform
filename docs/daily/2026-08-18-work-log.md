### 1. resume/portfolio 재시작 루프 CPU 100% 장애 수정 ✅
- **증상**: resume/portfolio가 재시작 루프 반복, CPU 100% 지속
- **원인**: common 모듈 `NotificationService`가 `@RequiredArgsConstructor`로 `JavaMailSender` 필수 주입 → resume/portfolio는 메일 설정이 없어 빈 생성 실패 → `Restart=always` 무한 재시작 루프
- **해결**: `JavaMailSender`를 `@Autowired(required = false)` 선택 주입으로 변경, null 체크 후 로그만 남기고 스킵
- **커밋**: `ea77d4c`

### 3. Grafana 알림 규칙 전 13건 등록 완료 ✅
- **서버(1~4)**: CPU 90%, Memory 90%, Disk 85%, Load 4 (node-exporter)
- **서비스(5~7)**: 서비스 다운(`up{job="spring-boot"}`), 5xx 에러율, 응답 지연 P95
- **로그(8~11)**: 앱 에러 급증, 인증 실패 급증, nginx 5xx, 이상 접근 (Loki)
- **DB(12~13)**: 커넥션 풀 소진, Slow Query 증가 (Prometheus)
- **Server Offline 규칙은 제거 결정** — 단일 서버에서 서버가 죽으면 Grafana도 죽어 메일 발송 불가 → 외부 uptime 서비스로 대체 예정
- 규칙 번호는 이름 앞에 `[1]`~`[13]` 프리픽스로 정렬 (Grafana는 이름순 정렬)

### 4. Prometheus 스크랩 대상 확장 + DB 데이터소스 오류 해결 ✅

- DB 알림 등록 시 **MySQL 데이터소스 선택 실수** → "failed to connect to server" → **Prometheus 데이터소스**로 변경하여 해결 (메트릭 출처는 mysqld_exporter 경유)

### 5. Nginx Web Log 대시보드 생성 (Loki) ✅
- **패널 1**: 상태코드별 분포 — `| pattern` 파서로 `status` 라벨 추출
- **패널 2**: access 로그 목록 — `{job="nginx", type="access"}`
- **패널 3**: 요청 수 — `sum(rate({job="nginx", type="access"}[5m]))`
- **학습**: nginx 로그는 JSON이 아니라 **combined 포맷**이라 `| json` 불가, `| pattern` 사용 필요

## 신규로 알게된 것 (2026-08-18)
- **Loki 보관 주기(retention)** 는 `limits_config.retention_period` + compactor로 설정 (기본 7일, `168h`)
- **로그 기반 알림(8~11)의 No data는 정상** — 해당 로그가 없으면 당연히 데이터 없음, 이상 발생 시에만 발화
- **nginx access 로그는 combined 포맷** → `status` 라벨 없음, `| pattern` 파서로 추출해야 `sum by (status)` 가능
- **DB 알림은 Prometheus 데이터소스 필수** — MySQL 데이터소스는 직접 DB 쿼리용, 모니터링은 mysqld_exporter 경유
- **DB 커넥션 알림은 WAS(HikariCP) 기준이 아니라 DB(MariaDB) 입장의 연결 수**
- **Load 평균 기준**: 단일 코어 서버에서 `cores × 4` = 4
- **P95 응답지연**: 히스토그램 활성화 필요, `is above` 값은 초 단위
- **Grafana SMTP**: 서버에서 메일 발송 설정 완료 (Step 1), 발송 테스트는 규칙 발화로 검증 예정
