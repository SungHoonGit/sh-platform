## 이슈 및 해결
- Modern 템플릿은 문서 내부에 자체 `max-w-3xl mx-auto`를 내장 → 좌측 컬럼 내 중첩은 무해, 레이아웃 변화 없음.
- IntersectionObserver만으로는 짧은 마지막 섹션이 관찰 밴드에 닿지 않아 하이라이트가 멈추는 케이스 발생 →
  passive scroll 리스너로 문서 바닥 근처(8px)에서 마지막 항목으로 보정.
- resume frontend에는 lint 스크립트 없음 → 검증은 `npm run build`(tsc -b && vite build)로 수행, 통과.
- 라이브 번들 마커 검증 시 `/?redirect=`는 미니파이어가 템플릿 문자열을 분리(`` `${ki}?redirect=` ``)해 단일 문자열 검색 실패 →
  `?redirect=`·`location.pathname+`·auth의 `` startsWith(`//`) `` 게이트로 재검증.
- `/scraper/actuator/health`가 배포 직후 502 → 30초 후 200 (재기동 transient, 기존과 동일).
- ui-shared `tsconfig.json`에 `paths`를 `compilerOptions` 바깥에 넣는 실수 → 즉시 `compilerOptions` 내부로 재작성.
- ui-shared `BlockConfirmDialog`에 `apiFetch(redirectOn401)`을 넣으려다 보류 — resume( hashRoute=true )와
  scraper(hash 불필요)에서 서로 다른 401 정책이 필요하므로, 공용 컴포넌트에는 토큰 유틸만 적용(정책은 앱 소유).
- 패키지 소스(`packages/shell`)는 app 디렉토리 밖 → `lucide-react`(그리고 react)가 node_modules 탐색으로 해석되지 않음.
  react는 기존 워링(3앱 paths+alias)이 이미 있었고, lucide-react는 3a에서는 미사용이라 문제가 안 되다가 3b에서 셸 4종이
  들어오며 노출 → 3앱에 동일 패턴의 `lucide-react` paths+alias 추가로 해결. (빌드가 잡아낸 타이밍: 3a 빌드=통과, 3b에서 필요)
- 3a/3b는 **순수 리팩토링**(런타임 동작 동일)이므로 마커 검증은 회귀 확인으로 실시 — `redirectOn401` 카운트가
  Phase 2 기준과 동일해야 함(platform 9·scraper 10·resume 8) → 실제 동일 확인.
- `loginUrlHere`는 미니파이어에서 식별자명이 사라져 라이브 번들 검색 불가 → 3a/3b는 asset 해시 변경 + health + 기존 마커로 검증.
