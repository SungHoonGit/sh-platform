## 첫 번째: 배포 검증 (사용자 확인 사항 — 서버에서)

`.env`를 `APP_SESSION_MAX_PER_USER=3` / `APP_SESSION_PREVENT_DUPLICATE=false`로 바꾸고
`sudo systemctl restart sh-platform-auth` 했다면:

1. PC·모바일 동시 로그인 → 둘 다 성공하는지
2. `redis-cli SMEMBERS user:sessions:2` → 기기 수만큼 Set 멤버 존재
3. 유령 멤버(Hash 없는 UUID)가 있으면: `SREM user:sessions:2 <uuid>`로 수동 정리

## 두 번째: Phase A-1 유령 세션 lazy cleanup 🟡 ✅ 완료 (`09e66ea`)

**재판정(08-25 심야)**: CLI에서 본 유령은 장애 대응 중 수동 청소가 반만 실행된 잔여물
(Hash만 DEL, Set 미삭제). 평시 코드 경로(removeSession/removeAllSessions/evict)는 전부 쌍으로 동작.
다만 **TTL 비대칭**(Set TTL=로그인마다 갱신 vs 개별 Hash 독립 만료)으로 로그인 간격이
벌어지면 정상 운영 중에도 저빌도 누적 → hardening으로 수행.

**구현 완료**: `SessionService.pruneAndGetActiveSessions()` — 조회 시 Hash 없는 멤버 SREM 정리.
getActiveSessionCount/getActiveSessions/createSession 한도 판정 전부 경유.
테스트 2건 신규(getActiveSessionCount_shouldPruneGhostMembers, createSession_shouldIgnoreGhosts_whenCheckingLimit).
**배포 후 검증**: 관리자 API `GET /api/v1/admin/sessions/{userId}` 호출 시 유령이 자동 사라지는지 확인.

```
private Set<Object> pruneAndGetSessions(Long userId):
    members = getSetMembers(...)
    for member in members:
        if !hasKey("session:{userId}:{member}"): removeFromSet(...)
    return 살아있는 것만
```

**준수**: Mockito 단위 테스트 추가(만료된 멤버 정리 케이스), `./gradlew :modules:auth:backend:test` 통과 후 커밋.
