## 첫 번째: 배포 검증 (사용자 확인 사항 — 서버에서)

`.env`를 `APP_SESSION_MAX_PER_USER=3` / `APP_SESSION_PREVENT_DUPLICATE=false`로 바꾸고
`sudo systemctl restart sh-platform-auth` 했다면:

1. PC·모바일 동시 로그인 → 둘 다 성공하는지
2. `redis-cli SMEMBERS user:sessions:2` → 기기 수만큼 Set 멤버 존재
3. 유령 멤버(Hash 없는 UUID)가 있으면: `SREM user:sessions:2 <uuid>`로 수동 정리

## 두 번째: Phase A-1 유령 세션 lazy cleanup 🔴 최우선

**문제**: 세션 Hash(`session:{userId}:{uuid}`)는 TTL 자동 만료되지만,
Set(`user:sessions:{userId}`) 멤버 제거는 명시적 호출일 때만 됨 → 좀비 UUID 잔존.
"활성 세션 수" 과대 계상 → max 오판/관리자 화면 오류.

**수정 위치**: `SessionService.java`의 `getActiveSessionCount`, `getActiveSessions`,
그리고 `createSession`의 count 계산부.

**방식**: 조회 시 각 member에 대해 Hash 존재 검사 → 없으면 `SREM` 즉시 정리 후 카운트.

```
private Set<Object> pruneAndGetSessions(Long userId):
    members = getSetMembers(...)
    for member in members:
        if !hasKey("session:{userId}:{member}"): removeFromSet(...)
    return 살아있는 것만
```

**준수**: Mockito 단위 테스트 추가(만료된 멤버 정리 케이스), `./gradlew :modules:auth:backend:test` 통과 후 커밋.
레이어 규칙/커밋 컨벤션은 AGENTS.md 그대로.
