## 7.4 Viewer 개선: 전체 탭 + 수집일시 표시 + 칼럼 정렬 (feat: 1a3e035)

- **배경**: 스크래퍼가 일자별 `{localPath}/{YYYY-MM-DD}.md`로 공고를 누적. 뷰어에서 사이트별 탭만 있고 "전체" 탭이 없어 신규 공고 전체를 보기 어려웠음. 파일 수집일시(파일 생성일) 표시가 없었고 칼럼 정렬이 불가능.

### 백엔드 (common)

- `FileController.getJobs`에 `sort`/`order` 파라미터 추가:
  - `sort` 허용값: `position` / `career` / `tech` / `location` / `deadline` / `site`, 기본(누락/불명) → `company`
  - `order` 기본 `asc`, `desc` 지원
  - `Comparator.comparing(..., Comparator.nullsLast(Comparator.naturalOrder()))`로 null 값은 항상 뒤로.
  - 필터 → 정렬 → 페이징 순서(기존 페이징 그대로).

### 프론트엔드 (scraper)

- `api/scraper.ts`:
  - `FileNode`에 `modifiedAt?` 추가 (백엔드 `/docs/tree`가 이미 반환).
  - `fetchJobs(rootPath, path, site, page, size, sort?, order?)` — sort 지정 시 `sort`/`order` 쿼리 추가.
- `components/FileTree.tsx`:
  - `onSelectFile`이 `FileNode` 전체를 전달하도록 변경(수집일시 전달용).
  - 파일 옆에 수집일(`modifiedAt`의 YYYY-MM-DD) 작게 표시.
- `pages/Viewer.tsx`:
  - **전체 탭**: 사이트 탭 좌측에 "전체" 버튼 추가 → `site=all`(필터 없음). 전체 탭에서만 "사이트" 칼럼 표시.
  - **수집일시 표시**: 선택 파일 헤더(`📄 {path}`) 옆에 `수집일시 YYYY-MM-DD HH:mm` 배지.
  - **칼럼 정렬**: 회사명/포지션/경력/기술/지역/마감/사이트 헤더 클릭 시 sort 전환(같은 키 재클릭 → asc↔desc, 다른 키 → asc). 정렬 시 페이지 1로 리셋, ▲/▼ 표시.
  - `formatDateTime` 헬퍼 추가.

### 검증

- 로컬: `:common:compileJava` 통과, `npm run build`(tsc -b && vite build) + `npm run lint`(oxlint) 통과.
- 배포: GitHub Actions `deploy-backend.yml` 4m29s 성공 (commit 1a3e035 push master).
- 배포 후(공개 URL):
  - `/scraper/actuator/health` → 200 UP, `/scraper/viewer?crawler=1` → 200 index.html.
  - 번들 `index-YlGxf8N8.js`에 `수집일시`, `전체`, `sort`, `마감` 마커 포함 확인.
  - `/docs/jobs` 정렬 응답은 인증 필요(토큰 없이 401) → 브라우저에서 로그인 후 확인 필요.

### 참고

- 백엔드 `deadline` 정렬은 문자열 비교(JobItem.deadline String) — 날짜형 정렬 정확성이 필요하면 파싱 개선 추후 검토.
- `/docs/jobs`는 계속 인증 필수.

## 7.5 Viewer 그리드 고정 + 스케줄 신규 등록 500 개선 (fix: ce9e989)

### 증상

1. **그리드**: 정렬/사이트 탭 전환 시 컬럼 너비가 내용에 따라 급변해 보기 어려움.
2. **스케줄 신규 등록**: 저장 시 `INTERNAL_ERROR`(500). `CrawlConfigService.createConfig`가 중복 이름일 때 `RuntimeException`을 던져 `GlobalExceptionHandler`의 `@ExceptionHandler(Exception.class)` → 500 `INTERNAL_ERROR`로 응답(메시지 번들도 없어 코드명 그대로 표시). 스크래퍼에 메시지 프로퍼티가 없어 오류 원인을 알 수 없었음.

### 수정

**Viewer 그리드 안정화 (frontend)**
- `table-fixed` + `<colgroup>` 고정 퍼센트 폭(6/7컬럼 분기). 헤더/셀 `text-sm` → `text-xs`, 패딩 축소.
- 긴 텍스트(기술 스택 등)는 셀 내 `<div class="truncate">` + `title` 툴팁으로 잘라 표시 → 컬럼 폭이 내용에 따라 변하지 않음.

**스케줄 등록 오류 개선 (backend)**
- `common ErrorCode`에 `DUPLICATE_NAME(HttpStatus.CONFLICT)` 추가.
- `CrawlConfigService`/`CrawlSiteConfigService`: `RuntimeException("Config not found"...)"` → `BusinessException(NOT_FOUND)`(404), 중복명 → `BusinessException(DUPLICATE_NAME)`(409).
- 스크래퍼에 `messages/messages_{ko,en}.properties` 번들 추가 + `application.yml` `spring.messages.basename: messages/messages, encoding: UTF-8` → 오류가 한글 메시지로 표시됨.

**스케줄 등록 개선 (frontend)**
- `handleSave`에서 기존 크롤러와 이름 중복(수정 중인 자신 제외) 사전 검증 → 즉시 안내.
- 사이트 설정 저장 `Promise.all` → `Promise.allSettled`: 한 사이트 실패가 전체 저장을 중단하지 않고, 실패 시 첫 실패 메시지로 안내(이전엔 INTERNAL_ERROR만 표시).

### 검증

- 로컬: `:modules:scraper:backend:test`(Mockito 단위테스트) + `:common:compileJava` 통과, 프론트 `npm run build`/`oxlint` 통과.
- 배포: GitHub Actions 4m6s 성공 (commit ce9e989 push master).
- 배포 후(공개 URL): `/scraper/actuator/health` 200 UP, 번들 `index-gXGCl-4r.js`에 `이미 같은 이름`, `allSettled`, `table-fixed`, `truncate`, `text-xs` 마커 확인.
- 409/404 응답 검증은 인증 필요 → 브라우저 로그인 후 재등록 시도로 확인. 만약 여전히 오류가 나면 이제 실제 원인 메시지(한글)가 표시되므로 재현 가능.
