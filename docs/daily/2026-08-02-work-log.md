
## 7.2 다중 클릭 방지 + Viewer 404 수정 (fix: 4f8f734)

- 다중 클릭: Schedule 저장 버튼을 `savingRef + isPending`으로 가드하고 저장 중 `저장 중...` 텍스트 + disabled 처리. 사이트별 설정 저장을 for-await → `Promise.all` 병렬화로 속도 개선(신규 config 중복 생성 방지).
- Viewer 404 원인: FileTree가 `/scraper/docs/list`를 호출했는데 **해당 엔드포인트가 백엔드에 없음** (common FileController는 `/docs/tree`, `/docs/jobs`만 제공). → FileTree를 `/docs/tree`(scan) 기반으로 재작성, 디렉터리 내비게이션 지원.
- 파일 없음 처리: common `FileController.getJobs`가 파일 미존재 시 `IllegalArgumentException`→500 대신 빈 결과 반환하도록 try/catch + 이중 파싱 제거. Viewer는 `res.ok` 실패 시 `{jobs:[],total:0}` 반환 → "데이터가 없습니다" 표시.
- 검증: 로컬 빌드·lint 통과, 배포 후 `/scraper/actuator/health` UP, 번들에 `/docs/tree`, `저장 중` 포함 확인, `/docs/tree`·`/docs/jobs`가 토큰 없이 401(핸들러 존재).
- 참고: `/docs/*`는 인증 필수. common FileController가 임의 `rootPath`를 받는 점은 잠재 보안 리스크(추후 rootPath 계정 검증 검토).

## 7.3 뷰어/스케줄 직접 접근 401 수정 (fix: fe651f9)

- 증상: 뷰어에서 `{"code":"UNAUTHORIZED","message":"Authentication required","status":401}`. 파일은 수동실행으로 생성됨(확인됨).
- 원인: nginx가 `/scraper/*`를 전부 Spring(8081)로 프록시. Spring에는 SPA 라우트(`/viewer`, `/schedule`, `/search`) 핸들러가 없음. 뷰어를 **직접 열거나 새로고침하면**(페이지 로드엔 Authorization 헤더 없음) Spring Security가 401 반환. `/scraper/`(루트)만 정적 index.html이 200.
- 수정:
  1. `SpaFallbackController` 추가 — `/search`, `/schedule`, `/viewer`를 `forward:/index.html`로 전달.
  2. `SecurityConfig` permitAll에 `/search`, `/schedule`, `/viewer` 추가 (API는 계속 인증 필수).
  3. 프론트 API 래퍼(`request`)에 401 시 토큰 삭제 + `/?redirect=/scraper/` 로그인 리다이렉트 추가(액세스토큰 1시간 만료 대비). FileTree/Viewer는 공용 `fetchFiles`/`fetchJobs` 헬퍼 사용.
- 검증(배포 후):
  - `/scraper/viewer?crawler=1`, `/scraper/schedule`, `/scraper/search`, `/scraper/` → 전부 200 text/html (index.html)
  - `/scraper/docs/tree`, `/docs/jobs`, `/crawl-config` → 토큰 없이 401 (API 보호 유지)
  - 번들 index-dQMNyOgu.js에 `/docs/tree`, `인증이 만료되었습니다`, redirect 포함 확인
