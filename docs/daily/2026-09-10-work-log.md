## 이슈 및 해결
- **배포 후 resume 서비스 502 (시작 실패)**: 커밋 `fef7136` 배포 후 resume만 502 (scraper 200, auth 302).
  - 원인: `SkillMatchServiceImpl`이 사용하는 `SkillMasterRepository.findByActiveTrueOrderByDisplayOrderAscNameAsc()`가 Spring Data 시작 시 엔티티의 `displayOrder` 프로퍼티를 검증하는데, `SkillMasterEntity`에 `display_order` 컬럼 매핑이 없어 `PropertyReferenceException` → 컨텍스트 로드 실패.
  - 해결: `SkillMasterEntity`에 `displayOrder` 필드 추가 (`@Column(name = "display_order")`), 커밋 `aa292f8` → CI 재배포(6m21s) 후 `resume/v3/api-docs` 200 복구 확인.
  - 교훈: DB 컬럼(DDL)과 엔티티 프로퍼티 매핑 불일치가 시작 실패로 이어짐 → 신규 쿼리 메서드 추가 시 `bootRun`/컨텍스트 로드 검증 필요 (로컬 DB 미기동이라 시행 시 H2 기동 필요).
- Mockito UnfinishedStubbing: 테스트 헬퍼 `master()`가 다른 스텁 인자 안에서 호출돼 `given(...)`이 중첩됨 → 각 테스트 시작에서 마스터 객체를 먼저 생성 후 repo 스텁
- 엔티티 protected 생성자 → `ResumeProjectEntity.create(userId)`/`ResumePortfolioItemEntity.create(userId)` 팩토리 사용 (기존 테스트 패턴 준용)
- **PDF 사용자 피드백**: (1) 클래식 사진 회색 보더가 사진을 안 감쌈 → header 2열 셀에 바로 response.addCell 하면 셀 폭(컬럼 30%)이 사진보다 커 보더가 넓게 잡힘. 모던/사람인형처럼 `setLockedWidth(true)+setTotalWidth(사진폭+4f)` 고정폭 photoBox로 감싸 밀착. (2) 사람인형 자기소개가 3page 공란·4page 시작 → `box().setKeepTogether(true)`가 긴 섹션을 통째로 다음 페이지로 밀어 페이지 끝이 비었음. `setSplitLate(false)`로 박스 본문이 페이지에 걸쳐 흐르게 수정("적당히 채우고 나머지는 다음 페이지").
- **1차 수정 재검증 테스트 신규**: `ResumePdfBlankPageTest` — ① 긴 자기소개 빈 페이지 없는지 ② 섹션 숨김(`included=false`)이 PDF에 반영되는지 ③ documentId 없는 경우 CLASSIC 기본 편성 폴백. 전부 통과.
- **1차 수정 후에도 자기소개 공백 잔존하여 재진단**: 바깥 `box`에는 `setSplitLate(false)`가 적용됐지만 본문을 감싼 **중첩 테이블 `bodyWrap`에는 분할 설정이 없어** 긴 본문이 통째로 다음 페이지로 밀릴 수 있었음. `bodyWrap`에 `setSplitLate(false)` + `setKeepTogether(false)` 추가 — 커밋 `637eea2`.
- **"프로젝트 숨김이 PDF에 보임" 재현**: 서버 측 배제 확인. `parseSectionKeys`가 `included=false` 섹션을 PDF에서 제외하며 위 재현 테스트로 증명. 사용자 실제 보고는 미리보기 링크 규칙이 PDF 다운로드 경로(`?documentId=`)에 누락됐거나 이전 배포 버전일 가능성 → 사용자 추가 확인 필요.
- **문서 목록 순서가 배포 때마다 리셋 (사용자 보고)**: 사용자 Network 확인 결과 `PUT /documents/reorder`(`{ids:[...]}`)는 200 정상. 원인은 `docs/resume/ddl-resume-v9.sql`의 UPDATE — 배포 워크플로우가 매 배포 실행하며 모든 문서의 `display_order`를 생성순(created_at,id)으로 강제 초기화. → 순번 초기화를 **컬럼이 신규 추가된 경우(`@col_exists=0`)에만** 실행하도록 PREPARE 조건 변경. 커밋 `c7d3c5d` → CI success(5m10s).
