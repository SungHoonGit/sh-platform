### 4. OAuth2 쿠키 역직렬화 오류 수정 (allowlist 함정) ✅
- **증상**: 간편로그인(카카오/네이버/구글/GitHub)이 확률적으로 실패 → `authorization_request_not_found` → 2~3번 시도하면 성공
- **원인**: `OAuth2AuthorizationRequest`의 `scopes`가 `Collections$UnmodifiableSet`으로 직렬화되는데, Spring Security 6.4의 allowlist에 이 타입이 없어 **쿠키 역직렬화 실패** → `loadAuthorizationRequest()` null 반환
  - **왜 확률적 실패였나**: 요청마다 직렬화되는 값 구조가 달라져 `UnmodifiableSet`이 아닌 경우는 통과 → "가끔 실패"처럼 보임
- **해결**: ObjectMapper default typing을 `NON_FINAL`로 + `java.util.*` 허용하는 PolymorphicTypeValidator 추가 (`CookieAuthorizationRequestRepository.java`)
  - **함정**: `EVERYTHING` 모드는 `readTree()`의 JsonNode까지 타입 강제해 별도 오류 → Spring Security 기본인 `NON_FINAL` 사용
- **검증**: `CookieAuthorizationRequestRepositoryTest` 4개 작성 (UnmodifiableSet 회귀 테스트 포함), 전체 통과
- **커밋**: `34b67e0`, 서버 배포 후 간편로그인 정상 확인 ✅
- **문서**: `docs/errors/007-260819-oauth2-cookie-deserialization-error.md` 작성

### 5. 스크래퍼 → 소셜 로그인 리다이렉트 문제 (원인 파악 완료, 수정 예정) 🔧
- **증상**: 스크래퍼에서 로그아웃 → 로그인 시 어디서 시작해도 항상 `/platform/`으로 이동
- **흐름 분석**:
  1. 스크래퍼 `/scraper/` 접근 → `AuthGuard.tsx:10`가 `/?redirect=/scraper/`로 이동 ✅
  2. 이메일 로그인은 `Login.tsx:37`이 `window.location.href = redirect` → `/scraper/` 정상 ✅
  3. **소셜 로그인 버튼(`Login.tsx:104`)이 `href="/oauth2/authorization/${p}"`로 그냥 이동 — `redirect` 파라미터 미전달** ❌
  4. 백엔드 `OAuth2SuccessHandler.java:54`가 `request.getParameter("returnUrl")`로 읽는데 null → `/platform` 기본값으로 리다이렉트
- **근본 원인**: OAuth2 인가 시작 URL(`/oauth2/authorization/{p}`)에 `returnUrl`을 전달하지 않아, 콜백에서 복원할 대상이 없음. (이메일 로그인과 달리 OAuth2는 redirect 파라미터 전달 경로가 없음)
- **해결 방향 (다음 작업)**: OAuth2 인가 URL에 `?returnUrl=` 추가 + 백엔드에서 콜백 시 파라미터 복원(추가 파라미터/쿠키) 처리

## 신규로 알게된 것 (2026-08-19)
- **Promtail relabel glob 함정**: 정규식은 대상 파일 경로가 아니라 **glob 패턴**에 적용될 수 있음 → `logs/*/*.log`에서 `*` 캡처. 서비스 구분은 **static_configs 정적 라벨**이 정규식보다 안전
- **Grafana 변수 (Label values 모드)**: `Label`엔 가져올 라벨명(`service`), `Stream selector`엔 **스트림만**(`{job="spring-boot"}`). `label_values()` 함수는 Query(LogQL) 모드용
- **Grafana 패널**: 하나의 패널 = 하나의 쿼리. Logs 시각화에는 로그 쿼리만, 메트릭은 별도 패널
- **Loki 라벨 값은 실제 푸시된 데이터 기준**: 새 라벨로는 새 로그가 쌓여야 스트림 생성 (서비스 재시작으로 로그 발생시켜 검증)
- **Promtail dry-run 권한**: ubuntu 계정으로 `promtail -dry-run` 시 positions.yaml permission denied — 설정 문법 자체는 통과, 무시 가능
- **Spring Security 직렬화 allowlist**: `OAuth2AuthorizationRequest` 직렬화 시 `Collections$UnmodifiableSet`/`UnmodifiableMap`은 allowlist에 없어 역직렬화 실패. `java.util.*` 허용 + `NON_FINAL`로 해결
- **확률적 실패 = 직렬화 포맷 가변성**: "가끔 되고 2~3번 하면 됨"은 근본 원인(역직렬화 호환성)이 있음을 의심해야 함
- **이메일 로그인 vs OAuth2 리다이렉트**: 이메일 로그인은 프론트에서 `redirect` 파라미터로 직접 이동하지만, OAuth2는 인가 URL→Provider→콜백 3단계라 `returnUrl`을 인가 시작 시점에 실어 보내야 함
