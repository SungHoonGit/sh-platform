## 잔존 switch 하드코딩 재진단 (mapCareerCode/mapCareerType)
- **SaraminCrawler.mapCareerCode → 삭제**. 메인 코드에 호출부 없음(죽은 코드). 사람인의 실제 URL 경력 파라미터는 `exp_cd`+`exp_min/max` 체계(appendCareerParams, 라인 180~187)라 career_level 코드(1/2/3/5/8/12)는 사용 안 됨. 동일 매핑이 DB(site_search_mapping id=1, career→career_level)에 이미 존재해 단일 소스 유지. 관련 테스트 7건(MapCareerCode 중첩 클래스) 함께 삭제.
- **SaraminCrawler.appendCareerParams 인라인 switch(exp_cd) → 유지**. `exp_cd`(1/2) + `exp_min/exp_max` 수치 구간을 함께 인코딩하는 복합체계 — 단일 코드 문자열 구조의 value_mapping으로 표현 불가. 동일 이유로 잡코리아 `mapCareerType`+`careerRange`(careerList 1/2 + 연수 구간)도 **유지**. DB 행(id=2, career→careerType, new/career)은 v2 API(careerList)가 아닌 레거시 API용이라 직접 대체 불가.
- **후속 과제(기록)**: site_search_mapping에 "코드+수치 구간" 류 복합 value type(예: range 템플릿) 추가 시 사람인/잡코리아 경력 파라미터도 DB화 가능. 설계 028/030과 별도 증분 작업으로 이어감.
