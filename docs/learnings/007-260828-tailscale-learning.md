## 1. 개념 설명

### 1.1 Tailscale이란?

**WireGuard 기반의 "오버레이 네트워크(VPN)" 서비스.** 기기들 사이에 **사설(가상) IP로만 통신하는 전용 네트워크**를 만들어준다.

```
[내 PC] ─────────┐
[노트북] ────────┤  →  Tailscale 가상 네트워크(100.x.y.z)  →  OCI 서버
[휴대폰] ────────┘         (공인IP 노출 없이 구성원끼리만)
```

설치하고 **같은 계정으로 로그인**하면, 어떤 인터넷 환경이든 기기들끼리 **바로(장치-대-장치, P2P) 암호화 통신**으로 연결됩니다.

> 한 줄 요약: **"공인 IP 설정 없이도, 전 세계 어디서든 내 기기들을 하나의 사설 LAN으로 묶어주는 마법."**

### 1.2 왜 그런 게 있는지 몰랐을까? (기존 VPN과의 인식 차이)

전통적인 VPN(회사에서 쓰는 IPSec/SSL VPN)은:
- 별도 **VPN 게이트웨이 장비/서버**를 사고, 설정하고, 인증서·클라이언트를 관리
- 원격으로 붙을 때마다 "회사 네트워크"라는 **중앙 집중식 터널**을 경유
- 복잡한 방화벽·NAT·포트포워딩 문제

Tailscale은 이걸 **완전히 SaaS화 + 오버레이 방식**으로 바꿉니다:
- 게이트웨이 장비 불필요 — **각 기기에 앱 설치만 하면 끝**
- 중앙 서버가 아니라 **기기 간 직접 터널(P2P) 형성**, 중앙은 최초 연결 도우미(coordination server) 역할만
- 방화벽/포트포워딩/NAT 우회를 자동 처리 (STUN/TURN, DERP fallback)
- → 그래서 "이런 게 있었나" 싶을 정도로 **설정 부담이 제로**

## 2. Tailscale vs SSLVPN (핵심 비교)

| 항목 | **Tailscale** | SSLVPN (예: OpenVPN SSL 모드, 상용 SSL VPN) |
|------|--------------|---------------------------------------------|
| 기반 기술 | WireGuard (커널 레벨, UDP) | SSL/TLS (TCP 443) |
| 네트워크 형태 | **Mesh (기기 간 P2P)** | Hub-and-spoke (게이트웨이 경유 중앙 집중) |
| 게이트웨이/장비 | 불필요 (SaaS) | 필요 (VPN 서버/장비) |
| 설정 난이도 | 앱 설치 + 로그인 = 끝 | 인증서·프로파일·정책 설정 복잡 |
| NAT/방화벽 통과 | 자동 (STUN/TURN/DERP) | 포트포워딩·방화벽 설정 필요 |
| 요금 | 개인 무료 티어 (100기기) | 대부분 유료 |
| 사용자 관리 | 계정(이메일/SSO) 단위 | AD/LDAP, PKI 인증서 기반 |
| 용도 | 개인·개발자·스타트업 원격 접근/메시 | 기업 원격 업무 표준 |

> **개념적 공통점**: 둘 다 "공인 인터넷 위에 암호화된 사설 네트워크 터널"을 만든다는 것은 같다.
> 그래서 "SSLVPN 같은 거구나"라고 생각한 것이 틀리진 않다. **차이는 '누가 터널을 어떻게 만드냐'** (장비냐 SaaS+wg, 중앙이냐 메시)이다.

### WireGuard vs OpenVPN (발전 단계)
- **OpenVPN** (전통): 사용자 스페이스에서 SSL/TLS, 호환성 높지만 느리고 설정 복잡
- **WireGuard** (최신): 커널 안에서 돌아 최소 코드·고속·간결. 2019년부터 Linux에 내장. Tailscale의 핵심 엔진

## 3. sh-platform에서의 실제 사용 (사용자 관점)

```
[집 PC (Windows)]  --Tailscale-->  [OCI 서버 140.245.95.162]
                   └ 사설 IP(100.x.y.z)로 SSH/웹 접근
```

- OCI 웹 포트를 **공인 인터넷에 직접 노출하지 않고**, Tailscale 사설망을 통해서만 접근 가능
- 여러 기기(PC/노트북/휴대폰)에서 **같은 사설망으로 묶여** 어디서든 개발·관리
- "단일 세션으로 관리" — 여러 기기에서 바이브 코딩하며 프로젝트 경로를 한 곳으로 통합

> 🛡️ 보안 메리트: 공인 IP 대신 **사설 IP로만 접근**하므로 스캐닝·무단 접근 공격면이 크게 줄어듦. SSH에 Tailscale만 허용하면 더 안전.

## 4. 주요 개념/용어

| 용어 | 설명 |
|------|------|
| **Tailnet** | Tailscale로 묶인 가상 사설 네트워크 자체 |
| **Node/Device** | Tailnet에 가입된 기기 하나 (100.64.0.0/10 대역 IP 부여) |
| **Coordination server** | 초기 인증·키 교환·연결 정보 교환만 돕는 중앙 (데이터 평면 아님) |
| **DERP** | P2P가 안 될 때 중계해주는 fallback 릴레이 서버 |
| **MagicDNS** | `<기기이름>.ts.net` 형태로 기기에 이름으로 접근 |
| **ACL (Tailnet Policy)** | 기기/사용자 간 접근 제어 규칙 (기본은 서로 접근 허용) |
| **Tailscale SSH** | SSH 키 대신 Tailscale로 인증하는 간편 SSH |
| **Subnet router / exit node** | LAN 전체 공유할 라우터 / 인터넷 출구로 쓰는 노드 |

## 5. 알아두면 좋은 배경 (왜 편한지의 이유)

1. **NAT 통과가 자동**: 집 공유기·이동통신망 뒤에서도 STUN으로 직접 연결 시도, 실패 시 DERP 중계 → 포트포워딩 불필요
2. **Zero-config 방화벽**: 물리 장비 설정이 아니라 애플리케이션 레벨로 통신 → 개방된 해야 할 포트가 사실상 없음
3. **암호화 기본 내장**: WireGuard가 모든 패킷 암호화 → 별도 TLS 설정 불필요
4. **개인 무료**: 100기기까지 무료, 초대 가능 → 가족/여러 기기 프로젝트에 적합
5. **오픈소스 헤드리스 도구 존재**: `tailscale up` CLI로 서버에도 설치 가능 → OCI ARM64 VM에도 headless 설치해 활용
