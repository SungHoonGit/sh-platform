## 2. 라이브러리 비교

### 2.1 Apache POI

| 항목 | 내용 |
|------|------|
| 최신 버전 | 5.5.1 (2025-11) |
| 라이선스 | Apache 2.0 |
| Java 지원 | 8+ (21 완전 호환) |
| Spring Boot | 공식 BOM 포함 |
| 포맷 지원 | XLS, XLSX, DOCX, PPTX 등 |

**장점:**
- 20년+ 생태계, 문서/커뮤니티 풍부
- 복잡한 스타일, 셀 병합, 수식, 차트 지원
- Spring Boot BOM에서 버전 관리 자동
- HSSF(XLS) + XSSF(XLSX) + SXSSF(스트리밍) 모두 지원

**단점:**
- 메모리 사용량 높음 (전체 행을 메모리에 로드)
- 코드량 25줄+ (셀 하나하나 수동 조작)
- SXSSFWorkbook 사용 시 `getRow()` 불가 (이미 flush된 행)
- XLS(XLS) 포맷은 65,536행 제한

**벤치마크 (100K 행):**
- 쓰기: **2,453ms**
- 읽기: **1,097ms**

---

### 2.2 EasyExcel (Alibaba)

| 항목 | 내용 |
|------|------|
| 최신 버전 | 3.1.2+ (유지보수 모드) |
| 라이선스 | Apache 2.0 |
| Java 지원 | 8+ |
| Spring Boot | starter 제공 (pig-mesh) |

**장점:**
- 어노테이션 기반 (`@ExcelProperty`)
- 메모리 효율적 스트리밍 (내부 SXSSF 자동 사용)
- 코드량 12줄+
- 셀 병합, 커스텀 컨버터 지원

**단점:**
- 2024년부터 공식 업데이트 느림 (유지보수 모드)
- POI 5.x 호환 시 `poi-ooxml-schemas` 제외 필요
- 복잡한 수식/차트 지원 제한적
- 문서가 중국어 중심

**벤치마크 (100K 행):**
- 쓰기: **542ms** (POI 대비 4.5배 빠름)
- 읽기: **334ms** (POI 대비 3.3배 빠름)

### 2.3 FastExcel (cn.idev.excel)

| 항목 | 내용 |
|------|------|
| 최신 버전 | 1.2.0 (2024) |
| 라이선스 | Apache 2.0 |
| Java 지원 | 11+ (21 완전 호환) |
| Spring Boot | starter 제공 (livk-cloud) |

**장점:**
- EasyExcel 원작자가 독립 개발
- 성능 최적화 (POI 대비 5~8배 빠름)
- 어노테이션 기반, 코드 간결
- PDF 변환 기능 내장
- 대용량 데이터에 최적화

**단점:**
- 아직 생태계 젊음 (2023~)
- 복잡한 스타일 지원 제한적
- 문서 부족 (영어/중국어 중심)
- 일부 고급 기능 미구현

**벤치마크 (100K 행):**
- 쓰기: **309ms** (POI 대비 **8배 빠름**)
- 읽기: **210ms** (POI 대비 **5배 빠름**)

## 4. 우리 프로젝트에 맞는 선택

### 현재 상황
- 이미 `poi-ooxml:5.2.5` 의존성 보유
- 채용공고 내보내기: 보통 **수백~수천 행** (10만 행 초과 거의 없음)
- 구조: 단순 테이블 (회사명, 포지션, 경력, 기술스택, 지역, URL)
- 복잡한 스타일/수식/차트 **불필요**

### 판단 근거

1. **"대용량" 기준**: 10만 행 이상은 사실상 드묾. 우리 프로젝트는 수백~수천 행이 일반적
2. **POI의 강점**: 복잡한 스타일/수식이 필요할 때만 유용. 단순 테이블에는 과도
3. **FastExcel의 강점**: 코드 간결성 + 성능. 유지보수 용이
4. **신규 도입 리스크**: FastExcel은 아직 젊지만, 단순 내보내기 기능은 안정적

### 최종 추천

| 선택 | 이유 |
|------|------|
| **FastExcel (추천)** | 코드 간결 + 성능优越 + 21 Java 완전 호환. 단순 내보내기에 최적 |
| Apache POI (대안) | 이미 의존성 있음. 복잡한 기능 필요 시 폐기 없이 유지 가능 |

### 선정 이유 (FastExcel)

1. **코드 간결성**: 어노테이션 1줄로 끝나는 내보내기
2. **성능**: POI 대비 8배 빠름 (대량 내보내기 시 체감)
3. **메모리 효율**: 스트리밍 방식으로 OOM 위험 낮음
4. **유지보수 용이**: 변경 지점 최소화
5. **Java 21 + Spring Boot 3.4 완전 호환**
6. **POI 공존 가능**: 기존 POI 코드와 충돌 없음 (별도 모듈)
